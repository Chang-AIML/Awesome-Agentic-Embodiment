# 综述写作流程（九步）与进度

> 流程来自用户 2026-10-10 给的「让 Claude 写一份 20 页左右的 survey 需要哪些流程」，要点照录。「进度」一节是 2026-10-10 对照仓库盘点的现状，「下一步的具体做法」是给接手的会话用的。
> 写作方案（章节、页数、待定问题）见 `docs/survey_plan.md`。它是 Claude Doc 的快照，原文档和讨论在 https://claude.ai/code/artifact/3814a79d-0de1-4954-9f8f-025f386674c9 。

---

## 为什么要这样安排

让 Claude 一口气写完 20 页的 survey，基本会出三类问题：

- 编造引用；
- 写成一篇一段的流水账，看不出脉络；
- 前后不一致：上百篇论文装不进一次对话，后面的章节会忘掉前面的术语和观点。

所以流程按「先建资料库、再定框架、然后分段写、最后独立核查」安排：

- 第 1、4、9 步由用户拍板，第 2、8 步用户抽查，其余由 Claude 做；
- 所有中间产物都存成文件（bib、卡片、大纲、术语表、各节 .tex），这样可以跨多次对话推进，不会因为上下文用完而断掉。

## 九步

1. **定题（用户定）。** 回答三个问题：这篇 survey 要回答什么问题、写给谁看、边界在哪（时间范围、哪些算、哪些不算）。最关键的是切入视角，比如按「方法在解决哪个核心难点」来分，而不是按年份排。
2. **建文献库。**
   - 来源：用户给 10–20 篇种子论文，顺着引用链往两头扩（它们引用了谁、谁引用了它们），再按关键词搜最近几个月的 arXiv；去重后由用户删减。
   - 产出：一个 .bib，每条带真实的 arXiv ID 或 DOI。
   - **铁律：参考文献只能从这个库里来，绝不凭记忆写引用。**
   - 规模：20 页大约对应 100–200 篇。
3. **论文卡片。**
   - 从原文抽固定字段：解决什么问题、核心想法（一两句大白话）、比前人新在哪、实验设定和关键数字、局限。
   - 可以开多个子任务并行。
   - 后面写作只能用卡片里有的内容，这样既防编造，也解决上下文装不下的问题。
4. **分类框架（最重要的人工节点）。**
   - 读完全部卡片，提 2–3 套分类方式。每套说明优缺点、每一类放哪些论文、哪些放不进。
   - 用户选一套或混搭，反复改。
   - 同时定下主对比表的列，即要比较方法的哪几个属性。
5. **带页数预算的大纲。**
   - 每节写清三样：一句话观点、分到哪些论文、占多少页。
   - 参考分配：引言 1.5 页，背景与问题定义 2 页，主体分类 9–11 页，数据集与评测 2–3 页，开放问题 2 页，结论 0.5 页。
6. **分节写作。**
   - 每节只给三样东西：大纲、该节的卡片、术语表。
   - 直接写 LaTeX，`\cite` 只能用 bib 里已有的 key。
   - 段落按想法组织，比如「这几篇都走 X 思路，区别在 Y」，不要一篇一段。
   - 引言和摘要最后写。
7. **统稿。** 统一术语、符号和叙述口径；补章节间的过渡和交叉引用；删掉重复内容。
8. **独立核查。** 换一个没参与写作的 agent 做，查三样：
   - 引用：每个 `\cite` 都在 bib 里，且句子里对这篇论文的说法能在卡片或原文里找到；
   - 数字：表格里的数字逐个对回原论文；
   - 覆盖：再搜一轮，看有没有漏掉的重要工作，尤其是最近 3–6 个月的。
9. **图表和终审。**
   - 分类树、发展时间线、主对比表，先用 TikZ 或 matplotlib 出初版。
   - 用户终审的重点是「开放问题」一节和各节里的判断性句子。这是 survey 真正的价值所在，也是 Claude 最容易写得四平八稳、没有观点的地方。

## 下一步的具体做法（按顺序）

### 第 3 步：论文卡片（先做这个）

**范围和输入**
- 范围：`data/core/paper_list.csv` 里保留 157 篇 + 资源 20 篇，共 177 篇。剔除的 9 篇不做。
- 全文：本机 `work/text_kept/`（151 篇）、`work/text/`（25 篇）、`work/text_bnd/`（1 篇），文件名是 `<arXiv 号>.txt`。
- `work/` 被 gitignore，不在 GitHub 上。换了机器，就用 `scripts/judging/fetch_fulltext.sh` 按 arXiv 号重新下载。

**产出**
- `data/cards/cards.jsonl`：每行一篇。
- 再写个脚本渲染成 `docs/cards/<Seat>.md`，方便用户读。

**字段**（值用中文写，数字和原文引用保留英文原文）：
- 从 `paper_list.csv` 直接带过来、不重抽：`key`、`arxiv`、`seat`、`role`、`topic`、`tier`、`year`、`decision_model`、`connection`、`evidence`。
- `problem`：解决什么问题，1–2 句。
- `idea`：核心想法，1–2 句大白话。
- `novelty`：比前人新在哪。点名前人工作时只用清单里的 `key`；清单外的写「清单外：<标题>」，留给第 2 步决定要不要入库。
- `agent_io`：agent 的输入、产出，以及产出交给谁（策略、代码、计划、动作、环境、奖励……）。
- `setup`：机器人或仿真平台、任务、基线。
- `numbers`：关键数字的列表，每条 `{claim, value, where}`，`where` 写表号或节号。
- `limits`：局限，分 `authors`（作者自述）和 `observed`（读者观察）。
- `quotes`：1–2 句原文，带节号。

**流程**（仿照 HANDOFF §5 的判定流水线）：
1. 提示词写在 `screening/prompts/card_extract.txt`。
2. 每片 8–10 篇，一个子 agent 抽一片。卡片质量要紧，建议用 Sonnet。
3. 另起一个子 agent 核查：每张卡的 `numbers` 和 `quotes` 能否在全文里 grep 到。全量查，至少也要抽 1/3。对不上的改掉或删掉。
4. 先做 Controller 和 Developer 两个 Seat，给用户看格式，再铺开到其余各 Seat。

### 第 2 步补完：.bib

- 写 `scripts/build_bib.py`：
  - 用 arXiv API（`export.arxiv.org/api/query?id_list=…`）取作者、标题、年份，生成 `survey/refs.bib`。每批不超过 50 个 ID，间隔 3 秒，遇到 429 就退避。
  - bib key 用「第一作者姓 + 年份 + 标题首个实词」（如 `liang2023code`），并在 `paper_list.csv` 加一列 `bibkey`。
- 背景文献（VLA、具身基础模型、相关综述）先列候选名单给用户确认，再入库，同样只按 arXiv ID 取元数据。
- 发表场所可以以后补。之前 OpenAlex 和 Semantic Scholar 都被限流过（HANDOFF §5）。

### 第 4 步收尾：对比表的列 + 术语表

- 对比表的候选列，给用户选：
  - 决策模型；
  - agent 产出（计划、代码、奖励、环境、动作……）；
  - 连到 Policy / Code 还是 Env / Sim；
  - 闭环（re-decide / authored / none）；
  - 身体（真机或仿真、机器人类型）；
  - 拓扑（×1 / ×R / ×N / 1:N）。
- 写 `docs/glossary.md`，包括：
  - 阶段、Seat、角色的中英文对照（英文见 `scripts/build_readme.py` 的 `ROLE_EN` 和 `SECTIONS`）；
  - G / FT / SPEC；
  - 三种闭环；
  - harness、carrier 等术语。

### 第 5 步：大纲补全

- 在 `docs/survey_plan.md` 的章节表上，每节加一句话观点和论文名单。名单可以从 `paper_list.csv` 的 seat / role / topic 自动生成。
- 观点等卡片做完再写，然后给用户确认。
- 评测一章的页数（现在 1 页）跟用户确认。

### 第 6 步起

- 目录用 `survey/`：`main.tex`、`sections/*.tex`、`refs.bib`、`figures/`。
- 先写 Controller、Developer 两章样章，用户确认写法和深度后再铺开。
- 第 8 步核查之前，先重跑一次 2026 年关键词检索，补最近的论文。上次检索到 2026 年 10 月初。
