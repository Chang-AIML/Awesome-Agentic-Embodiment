## The user's framework (follow it exactly)

Diagram: Agent -> Policy / Code / None -> Env / Sim; the agent may also act on Env / Sim directly; information
from Env / Sim may flow back to the agent. Not every arrow has to exist: the agent only has to connect to
Policy / Code or to Env / Sim.

Four hard rules:
1. The agent must be a GENERAL LARGE MODEL used as-is: an off-the-shelf LLM / VLM / MLLM (GPT-4/4o/5, Gemini,
   Claude, GPT-6 Astra, Qwen-VL / Qwen2.5-VL-72B-Instruct, Llama, DeepSeek, InternVL ...) driven by prompting,
   in-context examples, tools, memory or a harness. A model the authors trained, fine-tuned (SFT / LoRA / RL),
   or distilled is NOT a general large model ("通用大模型，而不是被训练过的小模型"), even if its base was general.
   VLAs, robot foundation models, specialist perception / failure / reward models do not count either.
   - Trained models are fine as TOOLS the general agent calls (skills, VLAs, detectors, planners).
   - Experience transfer counts: if the general model itself acts as the agent (in sim or on the robot) and
     its own trajectories / experience are distilled into a policy or a smaller model, keep it (Teacher, role 示范/蒸馏).
     But if the only "agent" at run time is the authors' trained model and no general model acts as an agent
     in the paper's system, exclude.
   - If a paper reports both, judge by its headline system / main results.
2. The agent must connect to Policy / Code (writes or selects programs, plans, constraints, skill / VLA calls,
   rewards, environments, system edits) or act on Env / Sim directly (emits actions). Open loop is fine.
3. At a glance the paper must be ABOUT the agent. If the headline contribution is a dataset, a data-generation
   or data-collection platform, or a benchmark, and the LLM is one component inside it, it is not an agent
   paper (example: RoboTwin 2.0, a bimanual data generator and benchmark whose MLLM writes task code). A
   benchmark or evaluation study whose subject is general LLM / VLM agents is a resource.
4. Env / Sim scope (user, 2026-10-09). Counts: real robots (arms, mobile robots, humanoids, legged robots, drones,
   multi-robot teams), physics simulators, and discrete embodied simulators where the agent has a body in a 3D
   scene (ALFRED, VirtualHome, AI2-THOR / Habitat task graphs, R2R discrete navigation graphs). Does NOT count
   (剔除, even with a general agent): pure text worlds where observations and actions are only text (ALFWorld text
   version, TextWorld, ScienceWorld), autonomous driving (CARLA, nuScenes, highway-env, on-road vehicles), and
   systems with no robot or embodied body at all (web / GUI / software agents, chatbots, IoT orchestration).
   Games with an embodied avatar (Minecraft, Overcooked) are judged by rules 1-3 and noted in the reason.

Classification (for kept papers): two phases, five seats (user, 2026-10-09). The phase is decided by when the
agent's output is produced and used.
- 执行前 (pre-execution): the agent's output is produced before the robot executes the task and is frozen into
  the deployed system.
  · Designer: designs the learning problem. role 环境/重建 (generate or reconstruct environments, scenes, sim
    assets, digital twins) or 奖励/任务 (rewards, success checks, tasks, curricula).
  · Teacher: executes the task itself; its verified demos / experience become training targets for a policy or
    smaller model. role 示范/蒸馏.
  · Developer: modifies the system itself and keeps or reverts by trials. role 系统/代码 (training code, policy
    code bases, skill libraries, harnesses, planning domains) or 本体/工具 (morphology, hardware, tools).
- 运行时 (runtime): the agent acts while the robot executes the task.
  · Controller: decides what the robot does at each step. role 编排 (plans and calls skills, tools, motion
    planners, VLAs), 写策略 (writes the policy code / constraints / reward that runs now), or 直接动作 (the general
    model itself outputs the actions).
  · Supervisor: intervenes only on anomalies. role 监控/恢复 (failure detection, safety guardrails, recovery,
    asking for help).
For resources give the evaluated seat and role 评测. For excluded use "-" for both.
Common seat mistakes: a specification, goal, constraint, reward or program that the model writes for the CURRENT task
instance and that drives this execution is Controller (写策略 or 编排), not Designer; Designer outputs are used to
train or set up a learning problem before deployment. Developer needs the agent to change the system and keep or
revert by trials, not a one-shot program. A model that steps in only when the main controller stalls or fails is
Supervisor.

## How to read each paper

The full-text file is pdftotext output (thousands of lines). For each paper:
1. Read the first ~400 lines (abstract, introduction, contributions).
2. Grep the file (case-insensitive) for: GPT|Gemini|Claude|Astra|Qwen|Llama|LLaMA|DeepSeek|InternVL|LLaVA|
   fine-tun|finetun|LoRA|SFT|RLHF|GRPO|PPO|we train|trained on|distill|backbone|base model|implementation detail
   and read the surrounding lines of the method and experiment-setup sections.
3. Decide which model makes the agent's decisions in the headline system and whether the authors trained it.
Do not guess from the title; quote the paper.
If the file starts with "ABSTRACT ONLY", no full text could be found: judge from the abstract, quote it as evidence,
and start the reason with 「仅摘要：」. If the file is missing, empty or unreadable, write the line with verdict 剔除,
model_status NONE and reason 「无全文」 so it can be redone.

## Output: exactly one line per paper, 12 fields separated by |, no | inside fields

key|arxiv|decision_model|model_status|main_contribution|connection|verdict|seat|role|evidence|reason|multi_agent

- decision_model: the model(s) that make the agent's decisions in the headline system, with sizes if given
  (e.g. "GPT-4o", "Qwen2.5-VL-3B fine-tuned on AgentVLN-Instruct", "Gemini 1.5 Pro + trained RT-1 skills").
- model_status: G (general model used as-is is the agent) | FT (the agent is a model the authors trained /
  fine-tuned / distilled, and no general model acts as an agent) | SPEC (VLA, robot foundation model or other
  specialist model is the decision-maker) | NONE (no LLM / VLM decision-maker).
- main_contribution: AGENT | DATA | BENCH | OTHER
- connection: ≤15 English words: what the agent outputs and where it goes.
- verdict: 保留 (G + AGENT + connected + in scope) | 资源 (BENCH about general LLM / VLM agents, in scope) | 剔除 (anything else)
- seat / role: as above.
- evidence: ≤40 words quoted verbatim from the paper that settle model_status (add the section name).
- reason: one Chinese sentence explaining the verdict.
- multi_agent: Y or N (the user's multi-agent chapter, 2026-10-09). Y only if multi-agent is central to the
  headline system: (a) two or more robots / embodied agents (heterogeneous teams such as drones + ground robots
  included) whose tasks are allocated, planned or coordinated by general-model agent(s), centrally or one agent per
  robot; or (b) the paper presents its system as a team of two or more general-model agents with distinct roles that
  communicate, debate, negotiate or hand work to each other. N otherwise: one robot driven by a pipeline of several
  prompted LLM calls (planner + verifier) that the paper does not present as multi-agent, human-robot dialogue
  alone, or a single agent with subagent tool calls. Give Y / N for excluded papers too.
