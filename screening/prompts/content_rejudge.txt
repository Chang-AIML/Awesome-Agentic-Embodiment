## The user's framework (follow it exactly)

Diagram: Agent -> Policy / Code / None -> Env / Sim; the agent may also act on Env / Sim directly; information
from Env / Sim may flow back to the agent. Not every arrow has to exist: the agent only has to connect to
Policy / Code or to Env / Sim.

Three hard rules:
1. The agent must be a GENERAL LARGE MODEL used as-is: an off-the-shelf LLM / VLM / MLLM (GPT-4/4o/5, Gemini,
   Claude, GPT-6 Astra, Qwen-VL / Qwen2.5-VL-72B-Instruct, Llama, DeepSeek, InternVL ...) driven by prompting,
   in-context examples, tools, memory or a harness. A model the authors trained, fine-tuned (SFT / LoRA / RL),
   or distilled is NOT a general large model ("通用大模型，而不是被训练过的小模型"), even if its base was general.
   VLAs, robot foundation models, specialist perception / failure / reward models do not count either.
   - Trained models are fine as TOOLS the general agent calls (skills, VLAs, detectors, planners).
   - Experience transfer counts: if the general model itself acts as the agent (in sim or on the robot) and
     its own trajectories / experience are distilled into a policy or a smaller model, keep it (L2 经验迁移).
     But if the only "agent" at run time is the authors' trained model and no general model acts as an agent
     in the paper's system, exclude.
   - If a paper reports both, judge by its headline system / main results.
2. The agent must connect to Policy / Code (writes or selects programs, plans, constraints, skill / VLA calls,
   rewards, environments, system edits) or act on Env / Sim directly (emits actions). Open loop is fine.
3. At a glance the paper must be ABOUT the agent. If the headline contribution is a dataset, a data-generation
   or data-collection platform, or a benchmark, and the LLM is one component inside it, it is not an agent
   paper (example: RoboTwin 2.0, a bimanual data generator and benchmark whose MLLM writes task code). A
   benchmark or evaluation study whose subject is general LLM / VLM agents is a resource.

Layers (for kept papers):
- L1 准备层 (before execution): 环境/重建 (generate or reconstruct environments, scenes, sim assets, digital
  twins) · 奖励/任务 (rewards, success checks, tasks, curricula) · 本体/工具 (robot morphology, hardware, tools)
  · 系统/代码 (edit training code, policy code bases, skill libraries, harnesses; keep or revert by trials)
- L2 中间层 (the agent affects the robot through a middle layer): 策略生产者 (writes the policy code /
  constraints that run on the robot) · 编排者 (plans and calls skills, tools, motion planners, VLAs) ·
  经验迁移 (its experience / demos / trajectories are distilled into a policy or smaller model) ·
  运行时监控 (intervenes only on anomalies: failure detection, safety guardrails, recovery, asking for help)
- L3 执行层: 直接动作 (the general model itself outputs the actions during execution)
For resources use layer 评测L1 / 评测L2 / 评测L3 for what is evaluated, or "-". For excluded use "-".

## How to read each paper

The full-text file is pdftotext output (thousands of lines). For each paper:
1. Read the first ~400 lines (abstract, introduction, contributions).
2. Grep the file (case-insensitive) for: GPT|Gemini|Claude|Astra|Qwen|Llama|LLaMA|DeepSeek|InternVL|LLaVA|
   fine-tun|finetun|LoRA|SFT|RLHF|GRPO|PPO|we train|trained on|distill|backbone|base model|implementation detail
   and read the surrounding lines of the method and experiment-setup sections.
3. Decide which model makes the agent's decisions in the headline system and whether the authors trained it.
Do not guess from the title; quote the paper.

## Output: exactly one line per paper, 11 fields separated by |, no | inside fields

key|arxiv|decision_model|model_status|main_contribution|connection|verdict|layer|subtype|evidence|reason

- decision_model: the model(s) that make the agent's decisions in the headline system, with sizes if given
  (e.g. "GPT-4o", "Qwen2.5-VL-3B fine-tuned on AgentVLN-Instruct", "Gemini 1.5 Pro + trained RT-1 skills").
- model_status: G (general model used as-is is the agent) | FT (the agent is a model the authors trained /
  fine-tuned / distilled, and no general model acts as an agent) | SPEC (VLA, robot foundation model or other
  specialist model is the decision-maker) | NONE (no LLM / VLM decision-maker).
- main_contribution: AGENT | DATA | BENCH | OTHER
- connection: ≤15 English words: what the agent outputs and where it goes.
- verdict: 保留 (G + AGENT + connected) | 资源 (BENCH about general LLM / VLM agents) | 剔除 (anything else)
- layer / subtype: as above.
- evidence: ≤40 words quoted verbatim from the paper that settle model_status (add the section name).
- reason: one Chinese sentence explaining the verdict.
